## 2. Крутейшие наблюдения из твоего лога `lldb` (магия Стека под капотом!)

### Наблюдение №1: «Почему `n=4`, но стрелочка остановилась на `-> 4 if (n <= 0)`?» (строка 33 отчета)
В `lldb` стрелочка `->` показывает строчку, которая **только собирается выполниться на следующем шаге**, а не ту ветку, куда зашел код.
На строке 4 процессор только проверял условие `n <= 0`. Так как `n = 4`, условие оказалось ложным, строка 5 (`return 0;`) была пропущена, и выполнение перешло сразу к строке 7 (`long long total = 0;`).

### Наблюдение №2: Откуда в `total` взялось число `8303480224`, а в `result` — число `9`?! (строки 26 и 240 отчета)
Посмотри на свой лог `fr v` в момент входа в функцию, **до того**, как выполнилась строка инициализации переменной:
1. В `sum_of_squares` до выполнения `long long total = 0;` команда `fr v` показала:
   `(long long) total = 8303480224` — это **неинициализированный мусор на стеке**, оставшийся в оперативной памяти от загрузчика ОС `dyld`!
2. А теперь самое интересное! Когда `sum_of_squares(4)` завершилась (вернув багованное значение `9`), следом вызвалась `factorial(5)`. И до того, как выполнилась строка 20 (`-> 20 long long result = 0;`), команда `fr v` показала:
   **`(long long) result = 9`**!
   **Почему именно `9`?!** Потому что стек работает по принципу LIFO: когда `sum_of_squares` завершилась, её стековый фрейм освободился, и вызванная следом `factorial` разместила свою переменную `result` **по тому же самому физическому адресу в ОЗУ**, где секунду назад лежала переменная `total` со значением `9`! Память при выходе из функции не очищается нулями — там остаются старые байты, пока ты явно не запишешь поверх них новое значение.

## 3. Ответ на твой вопрос: разница между `++i` (префиксный) и `i++` (постфиксный инкремент)

В обоих случаях сама переменная `i` увеличивается на `1`. Разница в том, **какое значение возвращает само выражение** и нужно ли создавать временную копию:

### 1. Префиксный инкремент (`++i` — «сначала увеличь, потом отдай»)
Как он работает концептуально:
```cpp
// Псевдокод ++i:
i = i + 1;
return i; // Возвращает ссылку на уже увеличенный объект (0 копий!)
```
Пример:
```cpp
int i = 5;
int a = ++i; // i стало 6, и в 'a' записалось 6
```

### 2. Постфиксный инкремент (`i++` — «сохрани старую копию, увеличь, отдай старую копию»)
Как он работает концептуально:
```cpp
// Псевдокод i++:
int old_copy = i; // <-- СОЗДАНИЕ ВРЕМЕННОЙ КОПИИ старого значения!
i = i + 1;
return old_copy;  // Возвращает старое значение
```
Пример:
```cpp
int i = 5;
int b = i++; // i стало 6, НО в 'b' записалось старое значение 5!
```

### Почему в C++ в циклах `for (int i = 0; i < n; ++i)` принято писать `++i`?
- Для простого типа `int`, если ты не присваиваешь результат (`i++` просто стоит в заголовке цикла), компилятор достаточно умен, чтобы выкинуть временную копию и сгенерировать одну и ту же инструкцию `add`.
- Но в C++ (как мы увидим в разделе ООП и STL) по коллекциям ходят с помощью **Итераторов** (`for (auto it = vec.begin(); it != vec.end(); ++it)`), а итератор — это не просто `int`, это структура/объект! И для сложных объектов `it++` может реально создавать и уничтожать лишнюю временную копию на каждом шаге цикла.
- Поэтому по стандарту **C++ Core Guidelines**: всегда пиши **`++i`**, если тебе специально не нужно старое значение до увеличения.
